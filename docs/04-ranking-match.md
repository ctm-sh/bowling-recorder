# 04. 랭킹전·마스터즈 기획

> 상태: 구현 완료 (2026-11-09). 운영 DB에는 `supabase/migrations/0008_ranking_matches.sql`을 배포 전에 적용해야 한다.
> 근거: 운영진 답변, `볼링 점수 기록지.xlsx`의 `랭킹전` 시트(제1회~제22회).

## 한 줄 정의
한 달에 한 번 정도 3게임으로 치르는 상금 대회를 기록하고, 3게임 성적으로 상금과 마스터즈 진출자를 정한 뒤 단판 마스터즈 우승자까지 가린다.

## 정모와 다른 점
| | 정모 | 랭킹전 |
|---|---|---|
| 게임 수 | 4~5게임, 게임마다 팀 재구성 | **3게임, 팀 고정** |
| 팀 배정 | 랜덤 또는 직접 | **직접만** |
| 개인 핸디 | 상대방과의 핸디표 **차이** | 핸디표 **값 그대로** 기본, 합의로 수정 가능 (게임마다 적용) |
| 돈 | 진 팀이 게임비 부담 | 상금 지급 |
| 승률·상대 전적 | 반영 | **반영 안 함** |
| 에버·최근 폼 | 반영 | 3게임만 반영, 마스터즈는 제외 |

## 규칙

### 공통
- 개인 게임 점수 = 점수 + 핸디. 핸디 기본값은 참가자를 정할 때의 티어와 핸디표로 정해 저장한다 (이후 티어가 바뀌어도 그 회차는 그대로).
- 티어 미정 회원은 정모와 같이 가장 낮은 티어(14)로 계산한다.
- **핸디는 운영진이 사람별로 수정할 수 있다.** 정모처럼 기본값을 함께 저장해 "합의 조정"과 원래 값을 표시한다.
  - 수정은 1게임 점수를 입력하기 전까지 할 수 있다.  - 수정한 값은 3게임과 마스터즈에 똑같이 적용한다.  - 입력 범위는 정모와 같이 0~300이다.- 상금은 나누지 않고 **대표자 1명에게 전액** 지급한 것으로 기록한다. 대표자는 운영진이 결과 화면에서 고르고, 상금이 있는 회차는 마감하려면 지정해야 한다.
- 형식(팀전 / 점수 넘기기)은 참가 인원을 보고 운영진이 고른다. 앱은 인원 기준을 강제하지 않는다.

### 팀전 (상금 10만원)
- 팀 점수 = 팀원 3게임 점수 합 + (팀원 핸디 합 × 3) + (꼭두각시 점수 × 3).
- 팀은 2개 이상, 인원 차이는 최대 1명이다. 3게임 내내 같은 팀이다.
- 인원이 적은 팀에는 꼭두각시 점수를 게임마다 더한다. 기본값은 참가자 전체 에버 평균(정수 반올림)이고 운영진이 수정할 수 있다.
- 1등 팀의 대표자 1명이 10만원을 받는다. 대표자는 1등 팀원 중에서 고른다.
- 동점이면 핸디 합이 큰 팀이 아래다 (정모와 동일). 핸디까지 같으면 운영진이 정한다.- 검증 예 (제9회): 1팀 2,582 + 120×3 = 2,942 / 2팀 2,565 + 122×3 = 2,931 → 1팀 우승.

### 점수 넘기기 (상금 최대 10만원)
- 판정 점수 = 참가자 전원의 3게임 점수 합 + (전원의 핸디 합 × 3).
- 구간과 금액은 회차마다 입력한다. 금액은 10만원을 넘을 수 없고, 점수가 높은 구간일수록 금액도 커야 한다.
- 도달한 가장 높은 구간의 금액을 참가자 중 대표자 1명이 받는다. 구간 기준은 **이상**으로 판정한다.- 어떤 구간에도 못 미치면 상금이 없고 대표자도 지정하지 않는다.
- 예: 1,800점 5만원 / 2,000점 7만원 / 2,100점 10만원, 5명이 2,050점 → 대표자가 7만원 수령.

### 마스터즈 (우승 상금 3만원)
- 팀전·점수 넘기기 모두 진행한다.- 3게임 개인 총점(점수 합 + 핸디 × 3) 순으로 팀과 상관없이 상위 N명이 진출한다. N은 회차마다 입력한다 (엑셀 기록은 3~6명).
- 앱이 순위대로 후보를 채우고, 불참자를 빼면 다음 순위가 올라온다.
- 단판 점수 + 핸디가 가장 높은 1명이 3만원을 받는다.
- 진출 경계나 1등이 동점이면: 핸디가 작은 사람이 위. 그래도 같으면 운영진이 정한다.
## 사용 흐름

**S5. 랭킹전 (운영진, 현장)**
```
새 랭킹전 (날짜, 같은 달에는 하나만)
 ─▶ 참가자 선택 (체크 목록, 이름 검색)
 ─▶ 형식 선택 ─┬─ 팀전: 팀 수 선택 → 맨 위 팀 칸으로 드래그 앤 드롭 → 팀 칸에서 바로 핸디 수정 (팀별 핸디 합 표시) → 꼭두각시 확인
              └─ 점수 넘기기: 구간·금액 입력 → 핸디 수정
 ─▶ 1게임 점수 ─▶ 2게임 점수 ─▶ 3게임 점수   (게임마다 현재 순위 표시)
 ─▶ 3게임 결과 (팀 순위 또는 달성 구간, 개인 순위, 상금) ─▶ 대표자 지정
 ─▶ 마스터즈 인원 입력·진출자 확정
 ─▶ 마스터즈 점수 입력
 ─▶ 최종 결과 (상금 받는 사람 요약, 카톡용 텍스트 복사) ─▶ 마감
```
상단 단계 표시: `참가 → 구성 → 1·2·3게임 → 결과 → 마스터즈 → 마감`

- 점수 입력 도중 나가도 입력한 점수는 남고, 목록에서 이어서 진행한다.
- 점수를 입력하기 전까지는 앞 단계로 돌아가 참가자, 핸디, 팀을 바꿀 수 있다.
- 마감 전까지는 점수를 고칠 수 있고, 결과와 진출자는 다시 계산된다. 마스터즈 점수가 입력된 뒤 3게임 순위가 바뀌면 경고한다.
**S6. 회원 조회**
하단 `랭킹전` 탭의 목록 또는 회원 홈의 바로가기(진행 중인 회차, 없으면 가장 최근 회차)로 진입 → 상세에서 팀 순위·게임별 점수·개인 순위·마스터즈·상금 확인. 진행 중에는 15초마다 자동으로 새로고침한다. 내 기록의 에버·최근 폼에 3게임이 반영된다.

## 데이터 설계
정모 테이블(`sessions`, `games`, `teams`, `scores`)을 재사용하지 않고 **전용 테이블을 만든다.** 재사용하면 정산·승률·상대 전적·시트 내보내기의 모든 조회에 "정모만" 조건이 필요해서 빠뜨렸을 때 기존 기능이 틀어진다.

| 테이블 | 주요 컬럼 |
|---|---|
| `ranking_matches` | match_no(내부 순번, 화면에는 "2026년 11월 랭킹전"처럼 날짜로 표시), date, format(`team`/`target`), target_tiers(jsonb), team_prize, masters_prize, masters_size, prize_representative_id, masters_winner_id, closed_at |
| `ranking_teams` | match_id, team_no, fill_score, fill_score_default |
| `ranking_entries` | match_id, member_id, team_id(점수 넘기기는 null), tier_snapshot, handicap_snapshot(적용값), handicap_default(핸디표 기본값), masters_seed(진출 시 순번) |
| `ranking_scores` | entry_id, game_no(1~3), score |
| `masters_scores` | entry_id, score |

- 상금은 회차별로 저장한다 (기본 10만원·3만원). 나중에 금액이 바뀌어도 과거 결과는 유지된다.
- RLS는 기존 테이블처럼 켜고 정책은 두지 않는다.
- 에버·최근 폼: `member_stats`, `member_form` 뷰에 `ranking_scores`를 합친다. 정모 팀 구성의 에버 기준 배정·꼭두각시 기본값에도 자연히 반영된다.

## 구현 순서
1. **규칙 계산**: 순위·상금·진출자 계산 순수 함수와 테스트 (`lib/domain/rankingMatch.ts`). 엑셀 실제 회차를 테스트 데이터로 쓴다.
2. **DB 마이그레이션**: 테이블 추가. 실제 DB 적용은 별도 확인 후 진행한다.
3. **운영진 앞단**: 생성 → 참가자 → 형식 → 팀 배정 또는 구간 입력.
4. **점수와 결과**: 3게임 입력, 순위, 상금.
5. **마스터즈와 마감**.
6. **회원 조회와 기록 반영**: 결과 화면, 뷰 변경, 내 기록.
